# sesere（Zenn・2本ヒット・中央liked 1,050）

> 種類：**最小で刺す型**。測った34本で**もっとも短い本文（1,264字）で、もっとも高い評価（1,050いいね）**を取った人。

**一行でいうと**：
みんなが黙って我慢している症状を1つだけ名指しして、コピペ1個で終わる解決策を渡し、
「なぜ効くのか」を矢印1本で説明して、あとは何も足さない人。

---

## 1,264字で1,050いいねの内訳

ここが一番学ぶところなので、先に答えを書く。

**本文を短くしたのではない。本文の仕事を2つに絞った。**

| 本文1,264字の使い道 | 分量 |
|---|---|
| ①「この症状に心当たりがあるか」の確認 | 冒頭4段落・約300字 |
| ②「なぜ効くのか」の説明 | 約200字 |
| 残り | 成果物（64行のCLAUDE.md）をつなぐ接続文だけ |

**捨てたもの**：手順の説明、環境の明示、前提の棚卸し、比較表。
実測でも `env=0` `tables=0` `links=0` `li=1`。何も置いていない。

**記事の真ん中に座っているのは、そのまま貼れる成果物**。
本文はその額縁でしかない。だから短くて済んでいる。

---

## 読者の置き方

**読者を指定しない。症状で囲い込む。**

冒頭2文目がこれ。

> Claude Codeを使っている人ならみんな感じてると思いますが
> —— [Claude Codeの「すぐルール忘れる問題」を解決する超効果的な方法を見つけた気がする](https://zenn.dev/sesere/articles/0420ecec9526dc)

「〜向けの記事です」も「この記事では〜します」も書かない（`reader_head=0` `goal_head=0`）。
**ここで「自分のことだ」と思った人だけが残る設計。**

---

## 記事の骨格

H2は**3〜4本で打ち止め**。

```
【ルール忘れる問題】H2 4本・1H2あたり316字
1. なぜ語尾ルールだけは守られるのか      ← 症状の中の例外に目をつける
2. AI運用5原則                     ← 成果物（コピペできる全文）
3. まとめ：シンプルだけど超効果的          ← 効いた証拠
4. 追記: CLAUDE.md について           ← 限界の告白

【playwright mcp】H2 3本・1H2あたり513字
1. mcpの追加
2. mcpが動いているか試す
3. で、何が嬉しいの？                ← メリット説明を末尾に回す
```

### 型：症状 → なぜそうなるかの問い → 成果物 → 効果 → 限界の告白

2本目の3つ目「で、何が嬉しいの？」に注目する。
**普通の記事なら冒頭に置くメリット説明を、末尾に回している。**
手順を終えた人に、あとから価値を説明する順番。

## 1文・1段落の作り方

| 指標 | ルール忘れる問題 | playwright mcp |
|---|---|---|
| 本文字数 | 1,264字 | 1,539字 |
| 1文の平均 | 45.1字 | 34.0字 |
| 80字超え | 18% | 9% |
| 1段落の平均 | 55.7字 | 39.0字 |

**1段落＝1文。句点を打たずに改行で切る。**
24段落のうち句点で終わるのは3段落だけ（2本目は47段落中0）。

実際の1段落（これで1段落まるごと）。

> そのたびに「ルールを守ってください」と500000000回は打ち込みましたし、指摘し疲れて「/a」で「ルールを再確認してください」というカスタムコマンドまで組んで対処しているような状況でした
> —— 同記事

3つを1文に同居させている。

| やっていること | 効果 |
|---|---|
| 誰でも実際に打ったことのあるセリフを鍵カッコで出す | 読者が自分の場面を思い出す |
| 回数を「500000000回」とわざと壊れた数字にする | 実数ではなく体感の量が伝わる |
| 自作コマンドまで作ったという証拠を添える | 「ここまでやった」で共感が確定する |

長いのに詰まらないのは、読点で区切られた3つの節が**すべて同じ不満の反復**だから。

## むずかしい語の初出処理

**括弧書きの定義をしない。既知のものと並べる。**

> playwrightはpuppeteerと同じく、chromeなどのブラウザをjsで操作するやつなのですが
> —— [Claude Codeとplaywright mcpを連携させると開発体験が向上するのでみんなやろう](https://zenn.dev/sesere/articles/4c0b55102dcc84)

「やつ」で終わらせて、**正確さを捨てて通じさせている**。

もう1つは、**用語を説明せず動作で説明する**型。

> 次にclaude codeを立ち上げて/mcpと入力してみてください
> —— 同記事

読者は `/mcp` が何かを知らなくても打てる。

## 再現性の担保

| 項目 | ある／ない | どう書いているか |
|---|---|---|
| 環境・バージョン・日付 | **ない**（`env=0`／1） | 1本目は日付ゼロ。バージョンの代わりに「発展を待ちましょう」で時限性だけ示す |
| 手順の粒度 | ある | 1手順＝1コマンド＋結果1文。**矢印とイコールで1行に圧縮**（コマンド → 保存先 = 使いどころ） |
| 成功判定 | **ある。この人の一番強いところ** | 段階ごとに合格ラインを1文で置く（下記） |
| つまずき・失敗 | ある（2本目 `pitfall=6`） | 太字で隔離＋**消費時間の実数**（「1時間ハマった」） |
| 前提の棚卸し | **しない** | 代わりに情報源の当たり方を1文で渡す（「claude自身に質問すると大嘘をつくので」） |

### 成功判定の3段（ここが移せる一番の技）

> 表示されたらとりあえずクリアです
> —— 同記事

`claude mcp list` で表示される → `/mcp` で表示される → スクショが返る、の3段に分けて、
**どこまで進んだかを読者が自分で判定できる**ようにしている。

1本目の判定は「20チャットしても30チャットしても事前確認を行ってくれるようになった」。
**回数で書く。**

## タイトルと冒頭の型

タイトルは3点セット。

```
〈読者のセリフを鍵カッコで名詞化した症状〉 ＋ 〈解決する〉 ＋ 〈断定を外す語尾〉

Claude Codeの「すぐルール忘れる問題」を解決する超効果的な方法を見つけた気がする
└ 症状（読者のセリフ）      └ 解決する       └ 見つけた気がする
```

**「見つけた気がする」で断定を外しているのが要。**
これがあると「本当かよ」と開きたくなるし、外れても誰も怒らない。
2本目も「〜するのでみんなやろう」で、主張ではなく勧誘。

リード文は挨拶1行だけ。記事の目的を書かない。

> どうもこんにちは、Claude Codeで遊び始めて2週間くらいが立ちましたがまだまだ模索中です
> —— 同記事

**経験2週間という自己申告で、先に自分の権威を下げている。**

## この人の一番の武器

**「なぜ効くのか」を矢印1本の循環として文字で書くこと。**

第5原則を守る → 5原則すべてを表示する → 第5原則を書くルールも表示される →
次回も守る必要があると認識する → また5原則すべてを表示する。

ほかのライターは「こうすると速い」で止まる。
この人だけが**仕組みを1行の循環図として文字で書く**。図を使わずに。

## 着手点の置き方

**同じ1アクションを、記事の中盤と末尾で2回置く。**

- 中盤：成果物の直後に「上の内容をCLAUDE.mdにそのままコピペすれば動きます」
- 末尾：追記でもう一度「一度全ての設定ファイルを消してこのCLAUDE.mdだけを設置して試してみるのをおすすめします」

**着手点は1つだけ。ただし2回言う。**

## ひろほのブログに移せるもの

1. **タイトルを〈読者のセリフの鍵カッコ〉＋〈断定を外す語尾〉で作る。**
   「Claude Codeが◯◯してくれない問題を解決する方法を見つけた気がする」の形にする
2. **1段落1文・句点なし・改行で切るを本文全体に通す。**
   2,000字なら約40段落。1段落の平均は40〜55字に収める
3. **つまずきに消費時間の実数を添えて、太字で本文から隔離する。**
   「（1時間ハマった）」にあたる「2026年8月27日、これで40分溶かしました」を1行で置く

## 移せないもの

1. **成果物としてのコードブロック（64行）。**
   ひろほはコードなしの条件なので、この短さを支える柱がなくなる。
   **「そのまま貼れるプロンプト全文」を成果物に置き換えないと、この型は成立しない**
2. **前提の棚卸しをしないこと。**
   読者が「本業と兼務でホームページを任された担当者」なので、
   前提を飛ばすと最初の1手で止まる。sesereの読者（すでに日常で使っているエンジニア）とは違う
