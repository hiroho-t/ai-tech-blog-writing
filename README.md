# ai-tech-blog-writing

Claude Codeで**技術ブログ**（開発者向けの実践記・手順記事・解説記事）を書くときに参照する参考集。
Qiita・Zennの人気ライターを**1人ずつ**分析して、その人の型を取り出している。

**公開サイト**：https://hiroho-t.github.io/ai-tech-blog-writing/

コーポレートサイト・サービスサイト・LPの文面は別リポジトリ。
→ **[ai-site-writing](https://github.com/hiroho-t/ai-site-writing)**（[サイト](https://hiroho-t.github.io/ai-site-writing/)）
オウンドメディアの記事は別リポジトリ。
→ **[ai-site-writing-blog](https://github.com/hiroho-t/ai-site-writing-blog)**（[サイト](https://hiroho-t.github.io/ai-site-writing-blog/)）
スライド資料の文面も別リポジトリ。
→ **[ai-slide-writing](https://github.com/hiroho-t/ai-slide-writing)**（[サイト](https://hiroho-t.github.io/ai-slide-writing/)）

## このリポジトリが他と違うところ

**書き方を「読みやすかった」で終わらせない。全部数えてから読む。**

- Qiita 1,000本＋Zenn 1,920本＝**2,920本**を公開APIで集めて、タイトルの型と長さの効き方を測った
- そこから12人を選び、代表記事**34本**を21指標で機械的に測った
- **測る道具（`tools/`）をそのまま置いてある。** 半年後に同じ手順をなぞれば同じ数字が出る

取得日：**2026年9月20日**

### 測る道具 — `tools/`

| ファイル | 何をするか |
|---|---|
| `collect_qiita.py` | Qiita APIで母集団を集め、著者ごとに集計する |
| `collect_zenn.py` | Zennの公開JSONで同じことをする |
| `measure.py` | 記事1本を21指標で測る。Qiita（API）とZenn（HTML）の両対応 |
| `analyze_titles.py` | タイトル13の型の占有率と評価、長さと評価の関係 |
| `targets.tsv` | 測る記事の一覧（`site` / `author` / `ID or URL` / `label`） |
| `metrics.tsv` | 測定結果 |

```bash
python3 tools/collect_qiita.py                              # 母集団を集める
python3 tools/analyze_titles.py                             # タイトルの型を見る
python3 tools/measure.py tools/targets.tsv > tools/metrics.tsv  # 34本を測る
```

[出典.md](出典.md) に、測った34本の一覧と数値。

## 表記ルールは重複して持たない

漢字とひらがなの使い分け、カタカナの長音、数字、記号、敬語の距離感、上から目線の直し方は、
技術ブログもコーポレートサイトも共通なので、
[ai-site-writing](https://github.com/hiroho-t/ai-site-writing) 側の `rules/` を参照する。

記事のパーツ（タイトル・リード・見出し・本文・まとめ）の基本は
[ai-site-writing-blog](https://github.com/hiroho-t/ai-site-writing-blog) 側の `articles/` を参照する。
**このリポジトリは、そこに「技術ブログ特有のこと」だけを足す。**

## 使い方

案件ごとに、必要なファイルをClaude Codeに読み込ませる。スキルとしては登録していない。

```
apply/01_2000字の型.md と patterns/01_再現性の担保.md を読んでから、
「Claude CodeとNotionの連携」の記事構成を作って
```

```
writers/03_sesere.md と patterns/04_タイトルと冒頭.md を読んで、
この記事のタイトルと冒頭を3案出して
```

## 収集の方針

- 他人の記事は**短い引用（1件1文以内）＋出典URL**にとどめる。全文も長い段落も転記しない
- 流用するのは文そのものではなく、抽出した**型**と**数値のしきい値**
- **評価の絶対数で参考ライターを選ばない。** リンク集が上位を占めるため（→ `method/02`）
- **1人につき2本以上を読む。** 1本だけのバズは型として再現できない
- **「移せないもの」を必ず書く。** コード前提・図前提・文字数前提の技は、2,000字・写真なしには移せない
- **数字が変わったら、結論のほうを直す。** 結論に合わせて数字を選ばない
- オウンドメディアの記事（BtoBのSEO記事）は対象外 → [ai-site-writing-blog](https://github.com/hiroho-t/ai-site-writing-blog)
