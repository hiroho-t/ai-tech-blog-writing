# 分析のやり方

人気の技術記事を「なんとなく読みやすい」で終わらせないための手順。
**同じ手順をもう一度なぞれば、同じ数字が出る**ように書いてある。
新しいライターを足すときも、半年後にもう一度測り直すときも、この順番でやる。

---

## 全体の流れ

| 工程 | やること | 使う道具 | 出るもの |
|---|---|---|---|
| 1 | 母集団を集める | `tools/collect_qiita.py` `tools/collect_zenn.py` | 記事プール（JSON） |
| 2 | 一発屋を外して書き手を選ぶ | 同スクリプトの集計部分 | 候補ライターの表 |
| 3 | 型の偏りを見る | `tools/analyze_titles.py` | タイトルの型・長さの効き方 |
| 4 | 記事を機械的に測る | `tools/measure.py` | `metrics.tsv`（21指標） |
| 5 | **数字を主張に変える前に検算する** | `tools/robust.py` | **言ってよい主張／言えない主張** |
| 6 | 数字を根拠に読む | 人が読む | ライター別のページ |
| 7 | 自分の記事に移せるか判定 | 人が判断 | `apply/` |

工程4までは全部機械でやる。**工程6から先だけを人がやる**。
この線を引いておくと、「読みやすいと思った」が根拠になるのを防げる。

**工程5を飛ばすと間違える。** 実際、最初の版はここを飛ばして
「タイトルの型で評価が変わる」「長さは当たる確率を上げる」と書き、**どちらも誤りだった**。
→ `method/01` の訂正、下の5章

---

## 1. 母集団を集める

### Qiita

公開APIで、ストック数のしきい値を切って集める。認証なしで使える（1時間60回まで）。

```bash
python3 tools/collect_qiita.py   # stocks:>300 を100件×10ページ = 1,000本
```

中身は次の1行。ここを書き換えれば条件を変えられる。

```
https://qiita.com/api/v2/items?page=N&per_page=100&query=stocks:>300
```

**ストック（あとで読む）で切る。LGTMで切らない。**
LGTMは「良かった」の合図なので拡散に寄る。ストックは「自分の作業で使う」の合図なので、
手順として役に立った記事のほうが上に来る。

### Zenn

公開されているJSONを、いいね順でページ送りする。

```bash
python3 tools/collect_zenn.py    # 48件×40ページ = 1,920本
```

```
https://zenn.dev/api/articles?order=liked_count&page=N
```

### 集めた母集団の性質（ここを書かないと数字を読み間違える）

| | Qiita | Zenn |
|---|---|---|
| 集めた条件 | ストック300超だけ | いいね順で40ページ |
| 本数 | 1,000本 | 1,920本 |
| 中身 | **人気記事だけ**（LGTM中央527） | **直近8日間がほぼ全量（1,262本）＋それ以前は当たり記事だけ（658本）** |
| 使い道 | 「当たった記事に共通する型」を見る | 同じ層の中だけで比べる |

**どちらも「確率」の話には使えない。**

- Qiitaは当たった記事だけの打ち切り標本。**「この型だから当たる」とは言えない**。
  言えるのは「当たった記事にはこの型が多い」まで
- Zennは2つの層が混ざっている。**層をまたいで比べると、生存バイアスで差が出てしまう**（→ 5章②）

**当たる確率を出したいなら、全量の層だけを、評価が溜まる時間をそろえて取り直す必要がある。**
今のプールではできない。

## 2. 一発屋を外して書き手を選ぶ

1本だけバズった人を参考にすると、再現できない型を写してしまう。
そこで**同じ書き手がプールに2本以上入っているか**で足切りする。

```
本数 = プール内のヒット本数
中央LGTM = その人のヒット記事のLGTMの中央値
```

- **本数2本以上**が最低条件
- そのうえで、次の3種類から選ぶ。1種類に寄せない

| 種類 | 何を学ぶか | 見分け方 |
|---|---|---|
| 解説型 | 難しいことのほどき方 | 本文が長く、外部リンクが少ない |
| 実践記型 | 手順の再現性 | 一人称が多く、日付・バージョンが書いてある |
| キュレーション型 | **学ばない**（→ `method/02`） | 本文が短く、外部リンクが数十本 |

## 3. 型の偏りを見る

```bash
python3 tools/analyze_titles.py
```

タイトルを13の型で正規表現にかけ、**占有率**と**その型の評価の中央値**を並べる。

**ここで出た数字は、そのままでは使えない。必ず工程5（5章）にかける。**
→ 結果は `method/01_母集団の傾向.md`

## 4. 記事を機械的に測る

測る記事を `tools/targets.tsv` に1行1本で書く。

```
site<TAB>author<TAB>記事IDまたはURL<TAB>ラベル
qiita	Sicut_study	4f301d000ecee98e78c9	Docker入門
zenn	sesere	https://zenn.dev/sesere/articles/0420ecec9526dc	ルール忘れる問題
```

```bash
python3 tools/measure.py tools/targets.tsv > tools/metrics.tsv
```

Qiitaは API から本文のマークダウンがそのまま取れる。
Zennは記事ページのHTMLから `<div class="znc">` の中を取る。
取った本文は `bodies/` にキャッシュするので、2回目以降は通信しない。

### 測る21指標と、それで何が分かるか

| 指標 | 何を見ているか |
|---|---|
| `chars` | 本文の文字数（コード・画像の説明を除いた地の文だけ） |
| `h2` / `h3` | 見出しの数 |
| **`chars_per_h2`** | **H2あたりの文字数。読みやすさに一番効く指標**（後述） |
| `avg_sent` | 1文の平均文字数 |
| `over80` | 80字を超える文の割合（%） |
| `code` / `code_lines` | コードブロックの数と行数 |
| `imgs` | 画像・図の数 |
| `tables` | 表の数 |
| `li` / `ol` | 箇条書きの行数／そのうち番号付き（＝手順）の行数 |
| `bold` | 太字の数 |
| `links` | 外部リンクの数 |
| `reader_head` | 冒頭600字で読者を指定しているか（0/1） |
| `goal_head` | 冒頭600字で記事のゴールを言っているか（0/1） |
| `env` | 環境・バージョン・年月・「時点」の出現数 |
| `pitfall` | ハマった・失敗・注意点・エラーの出現数 |
| `firstp` | 一人称（私・僕・自分・筆者）の出現数 |
| `call` | 呼びかけ（〜しましょう・してください・みなさん）の出現数 |
| `hedge` | ぼかし（かもしれません・と思います・気がする）の出現数 |

### 指標の読み方（しきい値）

34本を測った実測の分布。**自分の記事を測ったとき、この帯に入っているかを見る**。

中央値の95%信頼区間は、**書き手を選び直すブートストラップ**で出したもの（→ 5章③）。

| 指標 | 中央（95%CI） | 25〜75%の帯 | 外れているときの意味 |
|---|---|---|---|
| `chars_per_h2` | 505字（**385〜680**） | 356〜699字 | **1,000字を超えたら見出しを足す。** 200字を割ったら刻みすぎで箇条書きに近い |
| `avg_sent` | 40字（**36〜48**） | 33〜48字 | 60字を超えたら文を割る |
| `over80` | 7%（**3〜12**） | 2〜12% | 20%を超えたら読み手が息継ぎできない |
| `firstp` | — | — | 0に近い＝論考型、20超＝体験記型。**どちらでもいいが混ぜない** |
| `call` | — | — | 0に近い＝対等、20超＝教える型。**読者の指定と合っているか** |
| `env` | — | — | 手順記事で0なら再現できない。論考記事なら0でよい |

`chars_per_h2` を主指標にしているのは、**直し方が一意に決まる**から。
1文を短くしろ・やさしく書けは抽象的だが、「1見出し500字を超えたら見出しを足す」は今すぐできる。
（`avg_sent` も調整できるが、文を割るとつながりが切れるので、見出しほど機械的には直せない）

## 5. 数字を主張に変える前に検算する

```bash
python3 tools/robust.py
```

`analyze_titles.py` と `measure.py` が出した数字を、次の4点で潰しにいく。
**1つでも引っかかったら、その数字は主張に使えない。**

### ① プラットフォームを混ぜていないか

**QiitaのLGTM中央は527、Zennのいいね中央は2。単位も母数も違う。**
足して1つの中央値にすると、測っているのは型の効き目ではなく
**「その型がQiita寄りかZenn寄りか」**になる。

最初の版はこれをやって、「してみた」を✕、「完全版」を◎と判定していた。
実際は**Qiita比率の順番と、混ぜたときの中央値の順番がそのまま一致していた。**

**→ 必ずサイトごとに分けて出す。**

### ② 標本の作られ方が、見えている差を作っていないか

`collect_zenn.py` が集めた1,920本の実体は、性質の違う2層だった。

| 層 | 本数 | いいね中央 | 本文字数の中央 |
|---|---|---|---|
| 直近8日間（1日20本以上＝ほぼ全量） | 1,262 | 1 | 5,328字 |
| それ以前（いいねが多くて残ったものだけ） | 658 | 184 | 11,148字 |

**古い層は「当たった記事だけ」が残る。そして当たった記事は長い。**
この2層をまたいで「長い記事は当たりやすい」と言うと、
**長さではなく「生き残ったかどうか」を測ってしまう**（生存バイアス）。

**→ 全量の層の中だけで、しかも評価が溜まる時間をそろえて比べる。
そこまでやって差が残らなければ、「この標本では答えが出ない」と書く。**

### ③ 書き手ごとの相関を無視していないか

測った34本は18人の書き手のもの。**同じ人の記事は似る。**
記事を34個の独立した標本として扱うと、信頼区間が実際より狭く出る。

**→ 記事ではなく「人」を選び直すブートストラップ（クラスタブートストラップ）を使う。**

その結果、1見出しあたり文字数の中央は505字だが、95%信頼区間は**385〜680字**だった。
**「505字」ではなく「おおよそ400〜700字」としか言えない。**

### ④ 作った判別規則を、作るのに使っていない記事で試したか

**少数の例から規則を作れば、その例では必ず当たる。** 当たり前だが、これを忘れる。

最初の版は KNR109 の2本から「リンク集の見分け方」を4基準で作り、
**その2本で完璧に当たるのを見て規則として載せてしまった。**

測っていない24本（まとめ系12本／それ以外12本）で試した結果。

| 成績 | 値 |
|---|---|
| 感度（まとめ系を正しく除外） | **25%** |
| 偽陽性（それ以外を誤って除外） | **17〜33%** |

**4分の3を見逃していた。** 規則の中身も、実は KNR109 の書式の癖を拾っていただけだった。

**→ 規則を作ったら、必ず作るのに使っていない記事に当てて、感度と偽陽性を出す。
そこまでやってから書く。**

### 検算の結論の書き分け

| 検算の結果 | 書き方 |
|---|---|
| 全体の中央と信頼区間が重ならない | 「高い」「低い」と書いてよい。ただし n も併記する |
| 重なる | **「差があるとは言えない」** と書く。◎△✕で並べない |
| n < 10 | **「判定せず」**。順位表に載せない |
| 標本の作られ方に問題がある | **「この標本では答えが出ない」**と書いて取り下げる |
| 規則が測っていない記事で当たらない | **規則をやめる。** 代わりに人が読む手順を書く |

**数字が主張を支えないと分かったら、主張のほうを取り下げる。
取り下げた記録は消さずに、訂正として残す**（`method/01` の1章・2章がその例）。

## 6. 数字を根拠に読む

ライター1人について、必ず次の順で書く。順番を変えない。

1. **一行でいうと** — その人の書き方を1文で
2. **読者の置き方** — 誰に向けて、冒頭でどう指定するか
3. **記事の骨格** — H2見出しを上から実際に並べる
4. **1文・1段落の作り方** — `metrics.tsv` の数値＋実例1つ
5. **むずかしい語の初出処理** — 言い換えの実例
6. **再現性の担保** — 環境／手順の粒度／成功判定／つまずき／前提の5点で○×
7. **タイトルと冒頭の型**
8. **この人の一番の武器** — 1つに絞る
9. **移せるもの／移せないもの**
10. **出典** — URL・LGTM・公開日・文字数

引用は**1件1文以内**にとどめ、必ずURLを添える。全文も長い段落も転記しない。
写すのは文そのものではなく、抽出した型。

## 7. 半年後にもう一度やるとき

- `tools/collect_*.py` を再実行して、プールを取り直す
- **`tools/robust.py` を必ず通す。**しきい値も判定も、ここを通ってから書き換える
- `writers/00_一覧.md` の「本数」「中央LGTM」を更新する。**2本未満に落ちた人は外す**
- `tools/targets.tsv` に新しい記事を足して `measure.py` を回し直す
- しきい値（`chars_per_h2` の帯など）が動いていたら `method/00`（このページ）の表を直す

数字が変わったら、結論のほうを直す。結論に合わせて数字を選ばない。
