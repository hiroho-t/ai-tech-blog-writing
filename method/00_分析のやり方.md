# 分析のやり方

人気の技術記事を「なんとなく読みやすい」で終わらせないための手順。
**同じ手順をもう一度なぞれば、同じ数字が出る**ように書いてある。
新しいライターを足すときも、半年後にもう一度測り直すときも、この順番でやる。

---

## 全体の流れ

| 工程 | やること | 使う道具 | 出るもの |
|---|---|---|---|
| 1 | 母集団を集める | `tools/collect_qiita.py` `tools/collect_zenn.py` | 記事プール（JSON） |
| 2 | 一発屋を外して書き手を選ぶ | 同スクリプトの集計部分 | 候補ライターの表 |
| 3 | 型の偏りを見る | `tools/analyze_titles.py` | タイトルの型・長さの効き方 |
| 4 | 記事を機械的に測る | `tools/measure.py` | `metrics.tsv`（21指標） |
| 5 | 数字を根拠に読む | 人が読む | ライター別のページ |
| 6 | 自分の記事に移せるか判定 | 人が判断 | `apply/` |

工程4までは全部機械でやる。**工程5から先だけを人がやる**。
この線を引いておくと、「読みやすいと思った」が根拠になるのを防げる。

---

## 1. 母集団を集める

### Qiita

公開APIで、ストック数のしきい値を切って集める。認証なしで使える（1時間60回まで）。

```bash
python3 tools/collect_qiita.py   # stocks:>300 を100件×10ページ = 1,000本
```

中身は次の1行。ここを書き換えれば条件を変えられる。

```
https://qiita.com/api/v2/items?page=N&per_page=100&query=stocks:>300
```

**ストック（あとで読む）で切る。LGTMで切らない。**
LGTMは「良かった」の合図なので拡散に寄る。ストックは「自分の作業で使う」の合図なので、
手順として役に立った記事のほうが上に来る。

### Zenn

公開されているJSONを、いいね順でページ送りする。

```bash
python3 tools/collect_zenn.py    # 48件×40ページ = 1,920本
```

```
https://zenn.dev/api/articles?order=liked_count&page=N
```

### 集めた母集団の性質（ここを書かないと数字を読み間違える）

| | Qiita | Zenn |
|---|---|---|
| 集めた条件 | ストック300超だけ | いいね順で40ページ |
| 本数 | 1,000本 | 1,920本 |
| 中身 | **人気記事だけ**（LGTM中央527） | **直近の記事がほぼ全量＋過去の当たり記事**（2026年公開が1,372本＝71%、いいね2以下が52%） |
| 使い道 | 「当たった記事に共通する型」を見る | 「当たらなかった記事も含めた分母」で確率を見る |

Qiitaの側は当たった記事だけなので、**「この型だから当たる」とは言えない**。
言えるのは「当たった記事にはこの型が多い」まで。確率の話をしたいときはZenn側の分母を使う。

## 2. 一発屋を外して書き手を選ぶ

1本だけバズった人を参考にすると、再現できない型を写してしまう。
そこで**同じ書き手がプールに2本以上入っているか**で足切りする。

```
本数 = プール内のヒット本数
中央LGTM = その人のヒット記事のLGTMの中央値
```

- **本数2本以上**が最低条件
- そのうえで、次の3種類から選ぶ。1種類に寄せない

| 種類 | 何を学ぶか | 見分け方 |
|---|---|---|
| 解説型 | 難しいことのほどき方 | 本文が長く、外部リンクが少ない |
| 実践記型 | 手順の再現性 | 一人称が多く、日付・バージョンが書いてある |
| キュレーション型 | **学ばない**（→ `method/02`） | 本文が短く、外部リンクが数十本 |

## 3. 型の偏りを見る

```bash
python3 tools/analyze_titles.py
```

タイトルを13の型で正規表現にかけ、**占有率**と**その型のLGTM中央値**を並べる。
全体の中央値と比べて上か下かだけを見る。→ 結果は `method/01_母集団の傾向.md`

## 4. 記事を機械的に測る

測る記事を `tools/targets.tsv` に1行1本で書く。

```
site<TAB>author<TAB>記事IDまたはURL<TAB>ラベル
qiita	Sicut_study	4f301d000ecee98e78c9	Docker入門
zenn	sesere	https://zenn.dev/sesere/articles/0420ecec9526dc	ルール忘れる問題
```

```bash
python3 tools/measure.py tools/targets.tsv > tools/metrics.tsv
```

Qiitaは API から本文のマークダウンがそのまま取れる。
Zennは記事ページのHTMLから `<div class="znc">` の中を取る。
取った本文は `bodies/` にキャッシュするので、2回目以降は通信しない。

### 測る21指標と、それで何が分かるか

| 指標 | 何を見ているか |
|---|---|
| `chars` | 本文の文字数（コード・画像の説明を除いた地の文だけ） |
| `h2` / `h3` | 見出しの数 |
| **`chars_per_h2`** | **H2あたりの文字数。読みやすさに一番効く指標**（後述） |
| `avg_sent` | 1文の平均文字数 |
| `over80` | 80字を超える文の割合（%） |
| `code` / `code_lines` | コードブロックの数と行数 |
| `imgs` | 画像・図の数 |
| `tables` | 表の数 |
| `li` / `ol` | 箇条書きの行数／そのうち番号付き（＝手順）の行数 |
| `bold` | 太字の数 |
| `links` | 外部リンクの数 |
| `reader_head` | 冒頭600字で読者を指定しているか（0/1） |
| `goal_head` | 冒頭600字で記事のゴールを言っているか（0/1） |
| `env` | 環境・バージョン・年月・「時点」の出現数 |
| `pitfall` | ハマった・失敗・注意点・エラーの出現数 |
| `firstp` | 一人称（私・僕・自分・筆者）の出現数 |
| `call` | 呼びかけ（〜しましょう・してください・みなさん）の出現数 |
| `hedge` | ぼかし（かもしれません・と思います・気がする）の出現数 |

### 指標の読み方（しきい値）

34本を測った実測の分布。**自分の記事を測ったとき、この帯に入っているかを見る**。

| 指標 | 中央 | 25〜75%の帯 | 外れているときの意味 |
|---|---|---|---|
| `chars_per_h2` | 505字 | 356〜699字 | **1,000字を超えたら見出しを足す。** 200字を割ったら刻みすぎで箇条書きに近い |
| `avg_sent` | 40字 | — | 60字を超えたら文を割る |
| `over80` | 7% | — | 20%を超えたら読み手が息継ぎできない |
| `firstp` | — | — | 0に近い＝論考型、20超＝体験記型。**どちらでもいいが混ぜない** |
| `call` | — | — | 0に近い＝対等、20超＝教える型。**読者の指定と合っているか** |
| `env` | — | — | 手順記事で0なら再現できない。論考記事なら0でよい |

`chars_per_h2` を主指標にしているのは、**書き手が調整できる唯一の指標**だから。
1文を短くしろ・やさしく書けは抽象的だが、「H2あたり500字を超えたら見出しを足す」は今すぐできる。

## 5. 数字を根拠に読む

ライター1人について、必ず次の順で書く。順番を変えない。

1. **一行でいうと** — その人の書き方を1文で
2. **読者の置き方** — 誰に向けて、冒頭でどう指定するか
3. **記事の骨格** — H2見出しを上から実際に並べる
4. **1文・1段落の作り方** — `metrics.tsv` の数値＋実例1つ
5. **むずかしい語の初出処理** — 言い換えの実例
6. **再現性の担保** — 環境／手順の粒度／成功判定／つまずき／前提の5点で○×
7. **タイトルと冒頭の型**
8. **この人の一番の武器** — 1つに絞る
9. **移せるもの／移せないもの**
10. **出典** — URL・LGTM・公開日・文字数

引用は**1件1文以内**にとどめ、必ずURLを添える。全文も長い段落も転記しない。
写すのは文そのものではなく、抽出した型。

---

## 6. 半年後にもう一度やるとき

- `tools/collect_*.py` を再実行して、プールを取り直す
- `writers/00_一覧.md` の「本数」「中央LGTM」を更新する。**2本未満に落ちた人は外す**
- `tools/targets.tsv` に新しい記事を足して `measure.py` を回し直す
- しきい値（`chars_per_h2` の帯など）が動いていたら `method/00`（このページ）の表を直す

数字が変わったら、結論のほうを直す。結論に合わせて数字を選ばない。
