# 参考にする人の選び方

**評価の多い順に読むと、書き方の参考にならない記事から読むことになる。**
Qiitaのストック上位には、本文がほとんどないリンク集が並ぶ。
だが「短くて評価が高い」記事には、**学ぶ価値がいちばん大きいもの**も混じっている。
この2つを取り違えないための判別手順。

## 2. 比が高い記事は2種類ある。ここを取り違えない

中央値17.3に対して、70を超えたのは4本。うち**2本は学ぶ価値が最も高く、2本は最も低い**。

| | 短くて刺さった記事 | リンク集 |
|---|---|---|
| 例 | sesere 83.1／luvmini511 71.8 | KNR109 191.8／74.7 |
| 見出しが外部リンクの割合 | **0%** | **67%・75%** |
| env＋pitfall（日付・バージョン・つまずきの出現数） | 0〜2（少ないが本文に判断がある） | **両方0** |
| コードブロック・自作の図 | 4〜13本ある | **0本**（スクショだけ） |
| 一人称 | 1〜2回だが、自分の被害例が本文の柱 | 1〜2回。うち1回は自己宣伝 |
| 地の文がしていること | 症状の確認と「なぜ効くか」 | **「次に紹介するのは〜です」の受け渡し** |

**比だけでは区別できない。**

ただし、ここに並べた違い（見出しが外部リンクか、env＋pitfall が0か）を
**規則として他の記事に当てると当たらない**。KNR109に固有の特徴だった（→ 3章）。
**この表は「この4本がどう違ったか」の記録であって、判別の規則ではない。**

## 3. 判別の手順

> **訂正（2026-09-20）**
> 最初の版では、4つの基準（見出しリンク率・env+pitfall・1見出し字数・評価/100字）を挙げて
> 「2つ以上当てはまったら真似しない」という規則を書いていた。
> **この規則は KNR109 の2本だけを見て作ったもので、別の記事で試すと使えなかった。取り下げる。**

### 測っていない24本で試した結果

Qiitaプールから、KNR109以外で**タイトルが「まとめ系」の12本**と**それ以外の12本**を無作為に取り、
4基準を当てた（`python3 tools/robust.py` の4章で再現できる）。

| 基準 | まとめ系で当たる | それ以外で当たる |
|---|---|---|
| ①見出しが外部リンク30%超 | **2/12** | 0/12 |
| ②env＋pitfall＝0 | 3/12 | 4/12 |
| ③1見出しあたり350字未満 | 10/12 | 8/12 |
| ④評価／本文100字が50超 | 0/12 | 1/12 |

**「2つ以上で除外」の成績：感度25%／偽陽性17〜33%。**
**まとめ系の4分の3を見逃し、そうでない記事を2〜4本巻き込む。使えない。**

### なぜ外れたか

| 基準 | 何が起きていたか |
|---|---|
| ① | **KNR109の書式の癖**だった。見出しをリンクにするキュレーション書き手は12本中2本しかいない |
| ② | まとめ系にもそうでない記事にも同じくらい出る。**差がない** |
| ③ | **Qiitaの記事はもともと1見出しが短い。** 8割以上が350字未満で、除外の役に立たない |
| ④ | KNR109の191.8／74.7は**外れ値**。他のまとめ系は12本すべて50未満 |

**KNR109はキュレーション型の代表ではなく、極端な1例だった。**
2本から規則を作れば、その2本では必ず当たる。**作るのに使っていない記事で試さないと分からない。**

## 3-2. 代わりに使うもの

### ① タイトルで一次選別する（これが一番確実で、開く前に分かる）

```
まとめ／集／◯選／ロードマップ／チートシート／リンク集／資料／教材／一覧
```

Qiitaプール1,000本のうち**208本（21%）**がこれに当たる。

**ただし取りすぎる。** 検証した12本のうち少なくとも3本は、
タイトルに「まとめ」が入っていても中身は自分で手を動かした手順記事だった
（コードブロックが11〜34本ある）。**タイトルは一次選別まで。**

### ② 地の文を3段落だけ読む（機械では代わりにならなかった）

見るのは1つだけ。**地の文が、リンクとリンクの間を埋める接着剤になっていないか。**

| リンク集の地の文 | 学べる記事の地の文 |
|---|---|
| 「次に紹介するのは◯◯が公開している△△です」 | 「私の環境では〜がうまくいかなかったので、〜にした」 |
| 「〜になっています」「おすすめです」 | 「〜すると、〜が表示されれば成功」 |
| リンク先の目次をそのまま箇条書きにしている | 自分が確かめた日付・回数・金額が入っている |

**KNR109は「次に紹介するのは」13回＋「〜になっています」22回で本文2,312字。**
本文1,000字あたり5.6回。検証した24本では最大1.1回だったので、
**ここまで極端なら地の文を読めばすぐ分かる。** ただしその手前の記事は、読まないと分からない。

### ③ 判断がつかないときは、真似せずに内容だけ使う

**判別に時間をかけない。** 迷ったら「内容は読む、書き方は写さない」にする。
写す価値があるかどうかは、**その記事に自分が真似したい1文があるかどうか**で決まる。
1文も見つからなければ、それが答え。

## 4. 評価が多くても参考にしない3つの型

| 型 | 例 | なぜ参考にしないか |
|---|---|---|
| リンク集・チートシート集 | 「◯◯まとめ」「資料集」 | 地の文が繋ぎだけ。書き手の判断が1件も入っていない |
| ロードマップ・教材まとめ | 「これ全部やったら誰でも〜」 | 順番を並べているだけで、説明していない |
| 招待コード・無料で手に入れる系 | 「招待コードはコメントに」 | 情報の鮮度で取っている。半年後に読めない |

共通点は、**自分で同じ記事を書こうとしたときに「文章の技術」が要らない**こと。
集めるのは手間だが、書くのは難しくない。だから写しても自分の文章は上がらない。

## 5. この参考集で使った選定条件

1. **プールに2本以上入っている**（1本だけのバズを除く）
2. **タイトルが「まとめ系」でなく、地の文を3段落読んで接着剤になっていない**（→ 3-2章）
3. **次の5種類から、偏らないように選ぶ**

| 種類 | 何を学ぶか | 数字のしるし | この参考集の人 |
|---|---|---|---|
| 丁寧に教える型 | 難しいことのほどき方 | 本文1万字超、図が多い | Sicut_study、c60evaporator |
| 実践ガイド型 | 手順の再現性 | 一人称が多い、日付・バージョンの明示がある | morizyun、minorun365 |
| 最小で刺す型 | 問題の切り取り方 | 本文3,000字未満で高評価 | sesere、luvmini511、catnose99 |
| 言葉で伝える型 | コードを使わない説明 | コード0本、たとえと言い換えが多い | MinoDriven、kojimadev、rana_kualu |
| 正確さで読ませる型 | ごまかさない書き方 | 呼びかけが少ない、H2あたり1,000字前後 | uhyo、hirokidaichi |

**ひろほのブログ（2,000字・写真なし・コードなし・非エンジニア寄りの読者）に一番近いのは
「最小で刺す型」と「言葉で伝える型」。**
「丁寧に教える型」は長さそのものは移せないので、やり方だけを取る。

## 6. やってしまいがちな選び方

| ❌ | なぜ失敗するか |
|---|---|
| トレンド1位から読む | その日のトレンドは、鮮度で取っている記事が上に来る |
| 評価の多い順に読む | リンク集が上位を占める（→ 1章） |
| 有名な人だから読む | その人の当たり記事が1本だけなら、型として再現できない |
| 自分の分野の記事だけ読む | 書き方の型は分野をまたぐ。分野が違う人の型のほうが盗みやすい |
| 「読みやすかった」で選ぶ | 何が読みやすかったのかを数字に落とせない。次に活かせない |
